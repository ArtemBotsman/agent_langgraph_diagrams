# Baseline, методика и живые доказательства

Дата: 09.09.2026.

## Что означает baseline

`Baseline` (базовый ориентир) — заранее определённый более простой способ
решить ту же задачу. Он нужен, чтобы утверждение «агентный граф полезен» можно
было проверить сравнением, а не принять на веру.

В основном эксперименте используются одинаковый `SpecificationReq` (входная
спецификация), одинаковые Pydantic-контракты (проверяемые структуры) и один
gold (эталон), но три способа получения результата:

1. `B0_RULE` (правила) — LLM не используется; из требований строится один
   линейный сценарий. Это нижний ориентир стоимости и воспроизводимости.
2. `B1_ONESHOT` (один вызов) — DeepSeek одним ответом строит UC и activity,
   без critic (критика) и repair (исправления). Это проверяет, помогает ли сам
   граф, а не только модель.
3. `FULL` (полный граф) — два агента LangGraph: Use Case Agent и Activity
   Diagram Agent. В каждом есть generator, deterministic validation, critic и
   bounded repair (ограниченное исправление).

`Полезный смежный baseline` — метод, который решает не ту же, но близкую задачу
и поэтому показывает границу применимости. Локально проверен `Pyreverse`:
он проанализировал 28 Python-модулей и 54 import-связи и построил диаграммы
пакетов/классов. Однако его вход — уже существующий код, а наш вход — бизнес-
требования до написания кода. Поэтому Pyreverse нельзя подменять B0/B1, но
можно показать комиссии как честное сравнение `code → structure` и
`requirements → behavior`.

## Протокол repeated live pilot (повторного живого пилота)

- Кейс: `B1-DEV-001 RoomBook`, простой русскоязычный development case
  (случай для разработки).
- Повторы: 2 независимых запуска каждого условия B0/B1/FULL.
- B1 и FULL: `deepseek-v4-flash`, `temperature=0`, `thinking=disabled`.
- Автоматическая семантика: локальная
  `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`; входные
  тексты не отправляются третьему сервису.
- Hidden test (скрытый тест) не открывался и не использовался для настройки.
- Raw prompts/responses (полные запросы/ответы) не сохранялись; сохранялись
  хэши, роли, время, resolved model (фактическая модель) и token usage
  (расход токенов).

`artifacts/benchmark_runs/repeated-b0-b1-full-dev001-2026-09-09/results.json`.

## Полученные результаты и правильная интерпретация

### B0_RULE

- E2E success (успешность полного прохода): 100%.
- Semantic composite candidate (кандидат сводной семантической метрики): 0,633.
- Activity trace coverage (трассировка элементов activity): 100%.
- Среднее время: 0,0019 секунды; токены: 0; repair: 0.
- Стабильность диапазона результата: 1,000.

B0 формально корректен и дешёв, потому что строит упрощённый линейный результат.
Его 100% E2E не означает высокое смысловое качество: полнота акторов,
ветвлений и milestones (ключевых шагов) ниже.

### B1_ONESHOT

- E2E success: 0% — оба результата отклонены формальными валидаторами.
- Semantic composite candidate: 0,724.
- Activity trace coverage: 88,1%.
- Среднее время: 18,51 секунды; среднее число токенов: 8 969; repair: 0.
- Стабильность диапазона результата: 0,905.

B1 распознал смысловые элементы, но оставил непротрассированные activity edges
(рёбра диаграммы). Поэтому высокое сводное семантическое число нельзя считать
успехом pipeline (конвейера).

### FULL

- E2E success: 100% — оба запуска завершились успешно.
- Semantic composite candidate: 0,670.
- Activity trace coverage: 100%.
- Среднее время: 42,56 секунды; среднее число токенов: 33 445.
- В каждом запуске использовано 2 repair: по одному на каждую из двух activity-
  диаграмм.
- Стабильность диапазона результата: 0,941.

FULL обнаружил те же непротрассированные рёбра, пропустил дорогой critic при
известной формальной ошибке, исправил диаграммы, снова выполнил все проверки и
только после этого сформировал Mermaid. Цена результата — больше времени и
токенов. На этом пилоте доказана работоспособность механизма, но не
статистическое превосходство на всей предметной области.

## Почему сводный балл B1 выше FULL

Composite (сводный показатель) — только навигационная метрика dashboard
(панели), а не основной научный вывод. В B1 больше совпавших surface labels
(поверхностных формулировок), но есть формальная неполнота трассировки. FULL
прошёл строгий quality gate (барьер качества), лучше по milestone F1 и
hallucination proxy, но иначе декомпозировал текст. Поэтому в презентации нужно
показывать отдельные измерения и E2E, а не объявлять победителя по одному числу.

## Стоимость

В telemetry (телеметрии) стоимость сохранена как `null`: эксперимент не
подменяет фактический тариф догадкой. Если применить опубликованный DeepSeek
диапазон V4 Flash для cache-miss input/output, оценка одного среднего запуска
составляет приблизительно:

- B1: 0,004–0,008 USD;
- FULL: 0,011–0,023 USD.

Это расчётная вилка, не банковское списание. Источник тарифа указан в
`literature_2025_2026/SOURCE_MANIFEST.md`.

## Детерминированная трассировка и mutation test

Реализована цепочка типов:
`FR → FR atom → UC → scenario step → activity node/edge`, а также связи
`UC → user story/system story/activity`. LLM выбирает ссылки в типизированных
объектах; Python детерминированно материализует единый `TraceManifest`, строит
forward/reverse view (прямой/обратный вид) и проверяет, что обе стороны совпали.

Проверены 15 намеренных поломок: дубликат ID, неверный родитель atom, потерянная
и лишняя обратная связь, неверные типы концов, dangling target (висячая цель),
initial cardinality, неизвестное ребро, guard, происхождение узла/ребра,
partition, FR вне UC, неизвестный step и unsupported без объяснения.
Результат: 15/15 обнаружено, то есть 100% только для заранее определённых 15
классов. Это не доказательство семантической корректности любых диаграмм.

## Что остаётся до строгого научного DoD

- Два независимых эксперта должны заполнить подготовленные blind forms
  (слепые формы) по 30 кейсам; затем рассчитываются weighted Cohen's kappa
  (взвешенная каппа Коэна), exact agreement и agreement within one point.
- Руководитель должен письменно согласовать входную схему, Mermaid-профиль и
  benchmark policy.
- После экспертных исправлений создаётся final scientific freeze (финальная
  научная заморозка), Git tag и только один финальный запуск hidden test.
- Для утверждения порога «≥90% development cases» FULL нужно запустить на всех
  20 DEV-кейсах; текущий повторный пилот охватывает один кейс.
- Candidate semantic threshold (порог семантического сходства) нужно
  калибровать только на DEV по экспертным оценкам, не по hidden.

## Сопоставление с альтернативами

| Подход | Вход | Выход | Тип сравнения | Ограничение |
|---|---|---|---|---|
| B0 rules | SpecificationReq | тот же структурированный contract | прямой baseline | упрощённая семантика |
| B1 one-shot | SpecificationReq | тот же структурированный contract | прямой baseline | нет critic/repair |
| FULL LangGraph | SpecificationReq | UC, stories, activity, trace, quality | исследуемый метод | выше цена и задержка |
| Pyreverse | существующий Python-код | class/package graph | смежный baseline | код должен уже существовать |
| Mermaid CLI | готовый Mermaid | PNG/SVG/PDF | технический renderer | не интерпретирует требования |
| GitDiagram/DeepWiki | репозиторий | структура/документация | смежное внешнее решение | другой вход и этап разработки |

Статические и repository-to-diagram инструменты нужны в обзоре аналогов, но
научный вклад графа проверяется прежде всего одинаковым B1 one-shot на той же
модели, с тем же входом, контрактом и evaluator.
