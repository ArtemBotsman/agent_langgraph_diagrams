# Изменения после замечаний комиссии

1. **Слабый baseline.** Добавлены запрос с одной правкой по формальным ошибкам,
   разбиение по UC и внешний OpenCode Build. На историческом DEV20 одна правка
   и FULL дали 59/60 по общей проверке V1. Это уточняет прежний вывод, а не
   доказывает превосходство FULL над усиленным baseline.
2. **Лимит ответа.** В новых сериях предел 131072 выходных токенов на ответ,
   учёт finish_reason, обрезаний и стоимости. 8000 в примере CLI — прежний
   демонстрационный лимит. Все четыре больших cap2 запуска завершились без обрезаний.
3. **Эффект разбиения.** Добавлен метод по UC без критика и исправлений.
   Формальная ошибка после разбиения сама по себе не доказывает необходимость
   критика: требования схемы, ссылок и размер ответа учитываются отдельно.
4. **Оценка смысла.** Публикуются все пять Precision/Recall/F1. Gold и matcher
   не заменяют независимого эксперта. Внешние тесты кодогенерации — отдельный
   опыт, не объединённый с новыми сериями OpenCode.
5. **Температура.** В новых сравнениях фактическая T=0.2. Пилот T=0/0.2/0.7
   неполон; по правилу выбора сохранена 0.2. Оптимум не объявляется. Повторы
   на T=0 не называются независимой выборкой; ненулевая T также не доказывает
   независимость или статистическую значимость.
6. **Внешнее решение.** Добавлен настоящий OpenCode Build 1.18.33 с ограниченным
   файловым доступом. NOMAD остаётся теоретическим сравнением.

## Исправления реализации

Полный исходный контекст передаётся всем шести ролям. Activity-критик и редактор
получают словарь акторов. Текущие замечания отделены от истории. После конца
диаграммы обход не продолжается. Критик и раньше видел актуальный результат;
это не новая правка. Новые модули и регрессионные тесты публикуются вместе с отчётом.

Обычный CLI-профиль сохранён: он не равен исследовательскому FULL_NEW без
соответствующих зависимостей и адаптера параметров.

## Подтверждённый результат

На двух больших проектах FULL получил более высокий Milestone F1 и меньшее
время отдельного запуска. Цена выше, эффект по Trace и Branch неоднороден.
В серии размеров более высокий F1 этапов сочетается с меньшим Recall.
Технический результат — проверяемый пакет и измеренные условные преимущества,
не доказанное универсальное превосходство по трассировке.
