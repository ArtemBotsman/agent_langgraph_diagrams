# Словарь терминов

- `Agent` (агент) — управляемый компонент, который решает законченную задачу с
  помощью модели, инструментов, состояния и цикла проверки.
- `Use Case` (вариант использования) — сценарий достижения цели актором через
  взаимодействие с системой.
- `Activity Diagram` (диаграмма активности) — граф действий, решений и
  переходов процесса.
- `Root Graph` (корневой граф) — граф, который запускает и связывает подграфы.
- `Subgraph` (подграф) — самостоятельная часть общего графа.
- `Node` (вершина) — один вычислительный шаг.
- `Edge` (ребро) — разрешённый переход между шагами.
- `State` (состояние) — данные, передаваемые между вершинами.
- `Generator` (генератор) — роль, создающая первый вариант результата.
- `Critic` (критик) — роль, проверяющая смысл результата по заданным критериям.
- `Repair` (исправление) — повторная генерация с конкретным перечнем ошибок.
- `Validator` (валидатор) — детерминированная проверка формальных правил.
- `Router` (маршрутизатор) — функция выбора следующего ребра.
- `Renderer` (рендерер) — функция преобразования модели в отображаемый формат.
- `Mermaid` (текстовый язык диаграмм) — формат, из которого строятся SVG/PNG.
- `Traceability` (трассируемость) — возможность пройти от требования к элементу
  результата и обратно.
- `Benchmark` (тестовый набор) — зафиксированный набор входов и эталонов для
  сравнения методов.
- `Development split` (часть для разработки) — кейсы, доступные при настройке.
- `Hidden split` (отложенная контрольная часть) — кейсы, не используемые при
  настройке после заморозки набора.
- `Gold` (эталонная разметка) — ожидаемое смысловое содержание результата.
- `Baseline` (базовый метод сравнения) — более простой подход, с которым
  сравнивается основное решение.
- `Prompt` (инструкция модели) — текст, определяющий роль и задачу LLM.
- `LLM` (большая языковая модель) — модель, генерирующая и анализирующая текст.
- `API` (программный интерфейс) — способ обращаться к внешней модели.
- `Token` (токен) — единица текста, используемая для учёта объёма и стоимости.
- `Log` (журнал) — сохранённая техническая информация о выполнении.
- `Stub` (заглушка) — временная функция вместо ещё не реализованной логики.
- `Smoke test` (минимальный проверочный запуск) — один маленький запуск для
  проверки подключения и основных контрактов.
- `Scope` (границы задачи) — то, что входит и не входит в текущую работу.
- `DoD` (критерий готовности) — проверяемое условие завершения этапа.
