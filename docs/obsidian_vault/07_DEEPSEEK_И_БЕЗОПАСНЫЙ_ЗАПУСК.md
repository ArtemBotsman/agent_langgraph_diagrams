# DeepSeek и безопасное хранение ключа

## Текущее состояние

Ключ найден и безопасно перенесён:

- `.env` (локальный файл переменных окружения) содержит ключ;
- `.env` исключён из Git (системы контроля версий);
- `.env.example` (пример конфигурации) снова содержит пустое значение ключа;
- значение ключа не сохранено в документации или логах;
- endpoint `/models` успешно вернул HTTP 200;
- минимальный вызов `deepseek-v4-flash` завершился успешно и использовал 91
  токен: 87 входных и 4 выходных;
- это только smoke test (минимальная проверка), а не эксперимент качества.

## Почему нельзя хранить ключ в .env.example

`.env.example` обычно добавляют в репозиторий как пример. Настоящий ключ в этом
файле может случайно попасть на GitHub. `.env` предназначен для локальных
секретов и уже присутствует в `.gitignore` (списке исключений Git).

## Что проверить перед первым полным запуском агента

1. В кабинете DeepSeek проверить баланс и лимиты.
2. Ограничить первый `smoke test` (минимальный проверочный запуск) одним простым
   development-case (кейсом разработки).
3. Сохранить модель, дату, количество входных и выходных токенов, задержку и
   результат.
4. Не запускать сразу 30 кейсов с повторами.
5. После проверки одного ответа оценить примерную стоимость полного
   эксперимента.

## Старый ключ

Старый проект содержит другой жёстко записанный ключ. Его необходимо отозвать.
Даже если ключ давно не используется, безопаснее считать его раскрытым.

## Следующее действие

Проверка авторизации и минимальная генерация выполнены после явного разрешения
пользователя. Следующий порядок:

1. один полный `Use Case Agent` (агент вариантов использования) на
   `B1-DEV-001`;
2. проверка JSONL-log (построчного журнала JSON) без ключа и полного prompt
   (текста инструкции);
3. только затем решение о расширении эксперимента.
