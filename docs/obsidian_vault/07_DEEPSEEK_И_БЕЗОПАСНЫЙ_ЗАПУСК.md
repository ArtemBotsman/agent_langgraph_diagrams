## Текущее состояние

Ключ найден и безопасно перенесён:

- `.env` (локальный файл переменных окружения) содержит ключ;
- `.env` исключён из Git (системы контроля версий);
- `.env.example` (пример конфигурации) снова содержит пустое значение ключа;
- значение ключа не сохранено в документации или логах;
- endpoint `/models` успешно вернул HTTP 200;
- минимальный вызов `deepseek-v4-flash` завершился успешно и использовал 91
  токен: 87 входных и 4 выходных;
- это только smoke test (минимальная проверка), а не эксперимент качества.

## Почему нельзя хранить ключ в .env.example

`.env.example` обычно добавляют в репозиторий как пример. Настоящий ключ в этом
файле может случайно попасть на GitHub. `.env` предназначен для локальных
секретов и уже присутствует в `.gitignore` (списке исключений Git).

## Что уже проверено живым запуском

После smoke test (минимальной проверки) выполнены реальные запуски через
OpenAI-compatible API (API, совместимый с форматом OpenAI):

- `B0 rules` (детерминированная базовая линия): успешно, без LLM и без токенов;
- `B1 one-shot` (один LLM-вызов без графа исправления): формально не прошёл из-за
  неполной трассировки рёбер activity-диаграммы;
- `FULL` (полный граф с критикой, валидацией и ограниченным исправлением): успешно
  сформировал два UC, две activity-диаграммы и единый trace manifest
  (манифест трассировки).

Основной повторный эксперимент: по два запуска каждого режима на
`B1-DEV-001 RoomBook`. Средние значения:

- B0: `0` токенов, `0.0019` секунды, E2E success (успешное сквозное выполнение) `100%`;
- B1: `8 969` токенов, `18.51` секунды, E2E success `0%`;
- FULL: `33 445` токенов, `42.56` секунды, E2E success `100%`.

Результаты: `artifacts/benchmark_runs/repeated-b0-b1-full-dev001-2026-09-09/`.
Ключ, полные prompts (инструкции) и полные ответы модели в журналы не пишутся.

## Что проверить перед расширением эксперимента

1. В кабинете DeepSeek проверить баланс и лимиты.
2. Зафиксировать точные тарифы модели в переменных окружения, чтобы стоимость
   считалась автоматически, а не диапазоном.
3. Выполнить FULL минимум по всем 20 development cases (кейсам разработки) и
   не менять prompts (инструкции модели) между повторами одного эксперимента.
4. Не запускать сразу 30 кейсов с повторами.
5. После проверки одного ответа оценить примерную стоимость полного
   эксперимента.

## Старый ключ

Старый проект содержит другой жёстко записанный ключ. Его необходимо отозвать.
Даже если ключ давно не используется, безопаснее считать его раскрытым.

## Следующее действие

Проверка авторизации и минимальная генерация выполнены после явного разрешения
пользователя. Следующий порядок:

1. живой прогон FULL по 20 development cases с заранее установленным бюджетом;
2. не менее трёх повторов для оценки устойчивости;
3. экспертная разметка двумя экспертами;
4. только после этого — однократное открытие hidden gold (скрытого эталона).
