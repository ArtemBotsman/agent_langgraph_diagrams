# Как устроены папки проекта

Эта страница объясняет структуру для человека, который впервые открыл
репозиторий. За образец организации использована иерархия AppFactory-agents,
но исходный reference-проект не редактировался и его код не копировался.

![[assets/12_project_structure_2026_09_09.png]]

## Папка src/traceable_spec

Это production code (основной программный код).

- `agents/use_case/` — Use Case Agent (агент вариантов использования).
  `graph.py` хранит узлы и рёбра, `prompts.py` — инструкции generator, critic и
  repair (генератора, критика и исправления).
- `agents/activity/` — Activity Diagram Agent (агент диаграмм активности). Он
  строит типизированную activity model (модель процесса), проверяет её и только
  затем передаёт в Mermaid renderer (визуализатор Mermaid).
- `orchestration/` — root orchestrator (корневой оркестратор). Он вызывает
  первого агента, затем второго для каждого UC, объединяет trace (трассировку),
  запускает E2E validation (сквозную проверку) и evaluator (оценщик).
- `reference_methods/` — прямые baseline (базовые линии): правила B0 и один
  вызов LLM B1.
- `entities.py` — единые Pydantic contracts (проверяемые структуры данных).
- `traceability.py` — построение TraceManifest (манифеста происхождения).
- `validators/` — deterministic checks (повторяемые проверки Python-кодом).
- `evaluation/` — метрики benchmark (тестового набора).
- `llm/` — provider adapter (адаптер провайдера) без привязки графа к одному API.
- `mermaid/` — преобразование принятой модели диаграммы в Mermaid-код.

## Остальные верхнеуровневые папки

- `benchmark/` — входные кейсы, эталоны, hidden split (скрытая часть), freeze и
  формы двух экспертов.
- `configs/providers/` — примеры конфигурации DeepSeek и Groq/Qwen. Ключей там
  нет; рабочие ключи разрешены только в `.env`.
- `scripts/` — команды воспроизводимого запуска экспериментов.
- `artifacts/` — фактические результаты. Неудачные пилоты сохраняются как
  диагностическое свидетельство.
- `tests/` — автоматические тесты контрактов, графов, трассировки, провайдеров и
  freeze.
- `docs/obsidian_vault/` — объяснение проекта, материалы слайдов и защиты.
- `docs/project_context/` — долговременная история решений. Она не удаляется и
  не публикуется автоматически.

## Почему не повторена вся структура AppFactory-agents

AppFactory охватывает аналитика, архитектора, кодера, reviewer (проверяющего) и
deployer (развёртывание). Текущая НИР уже: только генерация UC/activity и их
проверка. Копирование всех ролей создало бы пустые папки и ложное впечатление,
что полный цикл реализован. Поэтому сохранён тот же принцип — папка на роль и
отдельная orchestration (оркестрация), — но только для фактического scope
(границ работы).
