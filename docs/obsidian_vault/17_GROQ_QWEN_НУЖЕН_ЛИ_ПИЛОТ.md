# Groq/Qwen: нужен ли дополнительный пилот

## Короткий ответ

Да, небольшой пилот полезен, но он не является главным блокером проекта.
Сначала нужно сохранить основное сравнение B0/B1/FULL на одной и той же модели.
Groq/Qwen добавляется отдельной проверкой переносимости результата на другого
provider (провайдера), а не заменяет DeepSeek задним числом.

## Фактическое состояние

- текущая модель: `deepseek-v4-flash`;
- текущий provider (провайдер): DeepSeek;
- текущий endpoint (адрес API): `https://api.deepseek.com`;
- предложенная модель: `qwen/qwen3.8-27b`;
- предложенный provider: Groq Free Plan;
- предложенный endpoint: `https://api.groq.com/openai/v1`;
- `GROQ_API_KEY` пока не настроен, поэтому Qwen-run не выполнялся.

Модель Qwen 3.8 27B официально доступна у Groq, имеет контекст около 131K,
максимум 16 384 output tokens (выходных токенов) и поддерживает strict JSON
Schema (строгое соответствие JSON-схеме). Официальные страницы:

- https://console.groq.com/docs/model/qwen/qwen3.8-27b
- https://console.groq.com/docs/structured-outputs
- https://console.groq.com/docs/rate-limits

На проверенную дату Free Plan указывает для модели 30 RPM (запросов в минуту),
1 000 RPD (запросов в день), 8 000 TPM (токенов в минуту) и 200 000 TPD
(токенов в день). Точный лимит организации всё равно нужно смотреть в Groq
Console (кабинете Groq).

## Что пришлось изменить в коде

OpenAI-compatible adapter (совместимый адаптер) теперь разделяет параметры
reasoning (рассуждения) по провайдерам:

- DeepSeek получает `thinking={type: disabled|enabled}`;
- Groq получает `reasoning_effort=none|default|low|medium|high` и
  `reasoning_format=hidden`;
- неизвестный совместимый provider не получает чужие специальные поля.

Это покрыто автоматическими тестами. Без такого разделения DeepSeek-поле
`thinking` могло привести к HTTP 400 на Groq.

Безопасный шаблон лежит в `configs/providers/groq-qwen.env.example`. API key
(ключ API) в шаблоне отсутствует.

## Рекомендуемый объём пилота

1. Smoke test (минимальная проверка) `/models` и один JSON-ответ.
2. `B1_ONESHOT` и `FULL` на `B1-DEV-001`, один повтор.
3. Если форматы проходят — второй повтор того же кейса.
4. Не использовать hidden split (скрытую часть).
5. Сохранять отдельный experiment ID (идентификатор эксперимента) с `groq-qwen`
   и не объединять строки с DeepSeek как будто это одна модель.

По DeepSeek-пилоту один B1+FULL использовал примерно 42 тысячи токенов, а два
повтора — около 85 тысяч. Это только ориентир: Qwen может расходовать иначе.
Такой объём укладывается в 200K TPD по порядку величины, но лимит 8K TPM требует
последовательного запуска и пауз либо корректной обработки HTTP 429.

## Когда эксперимент действительно нужен

Проводить сейчас, если нужно показать robustness (устойчивость) к смене модели
или использовать бесплатную квоту вместо расширения DeepSeek-пилота. Отложить,
если ближайшая цель — согласование постановки, Mermaid/UML-профиля, gold и
экспертов: эти решения сильнее влияют на научную корректность.

## Что разместить на слайде

Пока Qwen не запущен, не показывать его в таблице результатов. Можно указать в
future work (дальнейшей работе): «Cross-provider replication:
Qwen 3.8 27B / Groq Free Plan». После запуска добавить отдельные B1/FULL строки
с model ID, limits, E2E, токенами, latency (задержкой) и trace coverage
