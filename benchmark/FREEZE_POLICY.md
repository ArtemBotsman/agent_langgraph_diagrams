# Правило заморозки benchmark

Дата документа: **2026-08-21**, актуализировано **2026-09-09**.

## Два уровня фиксации

1. `author_technical_freeze` — автор фиксирует байты, split и SHA-256. Этот
   уровень уже создан в `v1_0_synthetic/freeze_record.json`.
2. `scientific freeze` — объявляется только после двух независимых экспертов и
   письменного согласования руководителя. Только после него допускается
   однократный hidden-run.

## Scientific freeze v1.0

После объявления freeze:

1. Запрещено добавлять/удалять/менять семантику **hidden**-кейсов.
2. Запрещено подстраивать промпты, пороги валидаторов и repair-политику под
   результаты hidden-прогонов.
3. Допускаются только:
   - исправление синтаксиса/схемы JSON без изменения смысла;
   - исправление явных опечаток в development-кейсах с записью в changelog;
   - добавление метрик evaluator без изменения gold.
4. Любое исключение требует письменного согласования с руководителем и записи
   в `CHANGELOG.md`/freeze metadata.

## До freeze

Можно исправлять development-набор, уточнять формат и калибровать
автоматические метрики только на development split. После author technical
freeze любое изменение требует записи в changelog и явного `--force`; оно
аннулирует предыдущие результаты, рассчитанные по старому hash.
