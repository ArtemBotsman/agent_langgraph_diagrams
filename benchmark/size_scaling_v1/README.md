# Size Scaling Benchmark v1

Дополнительный benchmark (тестовый набор) проверяет, как методы генерации
масштабируются при увеличении числа функциональных требований (ФТ). Он не
заменяет `benchmark/v1_0_synthetic`: первый benchmark содержит gold-разметку,
а этот набор пока содержит только входные `SpecificationReq`.

## Состав

- `G1_SMALL` — 5 проектов, 5–10 ФТ;
- `G2_GROWING` — 5 проектов, 11–20 ФТ;
- `G3_MEDIUM` — 5 проектов, 21–50 ФТ;
- `G4_LARGE` — 5 проектов, 51–75 ФТ.

Фактические значения: 6–10, 12–19, 24–48 и 54–74 ФТ. Каждый вход содержит все
шесть согласованных полей `SpecificationReq`, включая `project_task`.

## Что можно измерять автоматически

- долю полностью завершённых запусков;
- соответствие Pydantic/JSON-схемам;
- полноту покрытия ФТ и двусторонней трассировки;
- структурную корректность Activity Diagram;
- количество Use Cases, диаграмм, узлов, рёбер и trace links;
- задержку, число LLM-вызовов, токены, стоимость и repair attempts;
- совпадение результатов между повторными запусками.

## Gold-кандидат

Локальный `gold_candidate.json` содержит ожидаемых акторов, Use Cases,
обязательные этапы, ветвления и связи для всех 20 проектов. Он подготовлен по
входным требованиям до запуска сравниваемых систем и фиксируется SHA-256.
Поскольку разрешение на публикацию исходных проектов не записано, входы,
Gold-кандидат и экспертные формы пока исключены из Git.

Gold-кандидат позволяет выполнить предварительный единый расчёт метрик. Он не
становится утверждённой экспертной истиной автоматически: требуются две
независимые проверки по `GOLD_REVIEW_GUIDE_RU.md`.

Проверка и фиксация:

```bash
poetry run python scripts/validate_size_scaling_gold_candidate.py
poetry run python scripts/freeze_size_scaling_gold_candidate.py
poetry run python scripts/prepare_size_scaling_expert_review.py
```

## Ограничение выводов

В исходных файлах не было готовых Gold Use Cases или экспертных оценок.
Подготовленная авторская разметка не заменяет независимую проверку. Поэтому
структурно корректный или высокий автоматический результат нельзя считать
окончательным доказательством смыслового превосходства без экспертного этапа.

Основная проверяемая гипотеза: с ростом числа ФТ полный pipeline должен реже
терять требования и трассировку, чем один прямой вызов той же модели. Это
гипотеза до получения результатов, а не заранее заданный вывод.

## Воспроизведение

Подготовка локальных входов из исходного ZIP:

```bash
poetry run python scripts/prepare_size_scaling_benchmark.py \
  /path/to/benchmark_seed_projects_20.zip
```

Файлы входов локально лежат в `benchmark/size_scaling_v1/inputs/`. Они временно
исключены из Git до фиксации разрешения на публикацию. Проверяемые хэши, размеры
и распределение сохраняются в `manifest.json`.

Полный offline B0, три повтора:

```bash
poetry run python scripts/run_size_scaling_experiment.py \
  --condition B0_RULE \
  --repeats 3 \
  --experiment-id size-scaling-b0-r3-2026-09-13
```

Live-запуск выполняется только после настройки локального `.env` и явного
добавления `--allow-live` вместе с лимитами вызовов, токенов и стоимости.
