# Сопоставимый эксперимент GPT и Claude

## Цель

Проверить одну и ту же задачу в трёх условиях:

1. `B1_ONESHOT + GPT` — один запрос к GPT без критики и исправления;
2. `FULL + GPT` — GPT внутри двухагентного LangGraph pipeline;
3. `Claude one-shot` — один запрос к Claude с тем же входом и тем же выходным
   контрактом.

Во всех условиях входом служит `SpecificationReq`, а результат должен содержать
структурированные Use Cases, activity-модели и трассировку. Результаты
проверяются одним evaluator без ручной правки ответов.

## Порядок работы

### Шаг 1. Запуск GPT внутри репозитория

Открыть файл `01_GPT_PIPELINE_RUN_RU.md` и выполнить указанную там команду из
корня репозитория.

Основной экспериментальный скрипт:
`scripts/run_benchmark_experiment.py`.

### Шаг 2. Запуск Claude

Открыть `02_CLAUDE_DIRECT_RUN_RU.md`. Для каждого JSON из папки `inputs/` открыть
новый диалог, передать один входной файл и полный текст
`prompt/CLAUDE_PROMPT_RU.md`.

### Шаг 3. Сохранение результатов

Сохранить исходные ответы без исправления по структуре из
`03_RETURN_RESULTS_RU.md`. Для каждого кейса предусмотрены три независимых
повтора.

## Состав пакета

- `01_GPT_PIPELINE_RUN_RU.md` — точная команда запуска pipeline;
- `02_CLAUDE_DIRECT_RUN_RU.md` — порядок прямого запуска Claude;
- `03_RETURN_RESULTS_RU.md` — имена и структура возвращаемых файлов;
- `inputs/` — три development-входа разной сложности;
- `prompt/CLAUDE_PROMPT_RU.md` — полный prompt с правилами;
- `schema/OUTPUT_SCHEMA.json` — точный контракт результата;
- `responses/` — место для исходных ответов.

Hidden-кейсы, gold-разметка и API-ключи в пакет не входят.

## Что будет измерено

- `E2E success` — сформирован ли полный результат и пройдены ли проверки;
- Actor, Use Case, Milestone, Branch и Trace F1;
- доля неподтверждённых элементов;
- корректность схемы и ссылок;
- стабильность трёх повторов;
- число вызовов, токены, задержка и стоимость, если эти данные доступны.
