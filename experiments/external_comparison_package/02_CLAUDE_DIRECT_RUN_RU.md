# Прямой запуск Claude

## Что передаётся модели

Для одного запуска используются ровно два материала:

1. один JSON-файл из `inputs/`;
2. полный текст `prompt/CLAUDE_PROMPT_RU.md`.

Файл `schema/OUTPUT_SCHEMA.json` уже включён в prompt. Он приложен отдельно для
проверки структуры результата.

## Порядок запуска

Для каждого из трёх входов:

1. открыть новый диалог без истории других запусков;
2. приложить один `SpecificationReq` из `inputs/`;
3. вставить полный текст из `prompt/CLAUDE_PROMPT_RU.md`;
4. не добавлять поясняющих требований и не исправлять ответ вручную;
5. сохранить только исходный JSON-ответ;
6. повторить ещё два раза в новых диалогах.

Всего должно получиться девять ответов: три кейса по три повтора.

## Что должно быть в ответе

Единый JSON-объект со следующими верхнеуровневыми полями:

- `use_case_set` — акторы, Use Cases, основной, альтернативные и исключительные
  сценарии, User Stories и System Stories;
- `activity_diagrams` — одна типизированная activity-модель для каждого Use Case;
- `trace_manifest` — связи требований, Use Cases, шагов и элементов диаграммы.

Mermaid генерировать не требуется. После импорта он строится
детерминированным renderer из activity-моделей.

## Важное условие сравнения

Нельзя вручную исправлять ID, JSON, трассировку или содержание. Невалидный ответ
также является результатом эксперимента и должен быть сохранён без изменений.
