Use Case: UC-001 — Увеличить количество прямых бронирований и помочь хостес управлять столами без перепродажи вместимости, одновременно собирая депозиты для выбранных периодов обслуживания.
Goal: Увеличить количество прямых бронирований и помочь хостес управлять столами без перепродажи вместимости, одновременно собирая депозиты для выбранных периодов обслуживания.
Primary actor: ACT-001
Trigger: User starts the requested process
Preconditions:
Main success scenario:
  1. [STEP-UC001-001] Управляющий рестораном должен иметь возможность вести столы с номером, минимальным и максимальным размером компании и признаком активности.
  2. [STEP-UC001-002] Управляющий рестораном должен иметь возможность настраивать регулярные часы обслуживания и исключения для отдельных дат, когда ресторан закрыт.
  3. [STEP-UC001-003] Гость должен иметь возможность просматривать доступное время бронирования для выбранных даты и размера компании.
  4. [STEP-UC001-004] Гость должен иметь возможность создать бронирование, указав имя, номер телефона, адрес электронной почты, размер компании, выбранное время и необязательные заметки о потребностях в доступной среде или диетических ограничениях.
  5. [STEP-UC001-005] Система должна предотвращать превышение общей вместимости совместимых столов подтверждёнными бронированиями на один и тот же временной интервал.
  6. [STEP-UC001-006] После подтверждения бронирования система должна присвоить ему код и отправить гостю данные бронирования по электронной почте.
  7. [STEP-UC001-007] Гость должен иметь возможность изменить время или размер компании будущего бронирования с помощью его кода и адреса электронной почты при наличии текущей доступности.
  8. [STEP-UC001-008] Гость должен иметь возможность отменить будущее бронирование с помощью его кода и адреса электронной почты.
  9. [STEP-UC001-009] Для периодов обслуживания, требующих депозита, система должна создать сессию Stripe Checkout на настроенную управляющим сумму с человека.
  10. [STEP-UC001-010] Система должна подтверждать требующее депозита бронирование только после получения успешного платёжного webhook-события Stripe для соответствующей сессии.
  11. [STEP-UC001-011] Если свободного времени нет, гость должен иметь возможность встать в лист ожидания, указав дату, размер компании, предпочтительный интервал времени, имя, номер телефона и адрес электронной почты.
  12. [STEP-UC001-012] В панели хостес выбранный период обслуживания должен отображаться как хронологический список бронирований и записей в листе ожидания.
  13. [STEP-UC001-013] Хостес должна иметь возможность назначить подтверждённому бронированию один совместимый активный стол.
  14. [STEP-UC001-014] Хостес должна иметь возможность установить бронированию статус «прибыл», «посажен за стол», «завершено», «отменено» или «неявка».
  15. [STEP-UC001-015] Система должна отправлять напоминание по электронной почте за 24 часа до каждого подтверждённого бронирования, созданного не менее чем за 24 часа.
  16. [STEP-UC001-016] В отчёте по загрузке должны отображаться количество гостей, посаженные компании, неявки, отмены и использование столов для каждого завершённого периода обслуживания.
